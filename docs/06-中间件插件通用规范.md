# 06 中间件插件通用规范

> **本文定位**：定义 kinstall 所有非 Kubernetes 中间件插件（Valkey / Redis、PostgreSQL、MySQL、Elasticsearch / OpenSearch、对象存储及后续 Kafka / Nacos 等）共享的能力模型、部署规范、运维语义、监控日志接入、二期声明式插件包格式与三期 gRPC 外部插件协议。各组件具体设计见 `07`–`11`。
>
> **版本**：v1.1（S8/V，2026-11-26；v1.1 明确 systemd unit 可选 `-<role>` 后缀、将 §6 声明式包示例改为轻量组件 `zookeeper-plugin` 以遵循 ADR-069、同步 Garage 红灯与 Filebeat 客户自备规则）。版本号、Operator 状态与许可证信息截至 2026-11-26，引用前请复核。

## 1. 通用能力模型与主机部署规范（F1）

所有中间件组件插件必须遵循统一的文件系统、用户、systemd 与资源占用约定，确保多实例共存、可审计卸载与 CMDB 容量核算一致。

### 1.1 统一目录、用户与 systemd 规范（ADR-040）

| 维度 | 统一规范 | 说明 |
| --- | --- | --- |
| 二进制目录 | `/opt/kinstall/bin/<product>/<version>/` + 当前软链 `/opt/kinstall/bin/<product>/current` | 多版本并存，升级通过原子切软链完成 |
| 配置目录 | `/etc/kinstall/<product>/<instance>/` | 权限 `0750`，属主 `root:<svc_user>`；机密配置 `0640` |
| 数据目录 | `/data/<product>/<instance>/`（可经 `params.dataDir` 覆盖） | 独占数据盘挂载点（`03 §6.10`：XFS + `noatime`） |
| 日志目录 | `/var/log/kinstall/<product>/<instance>/` | 配套 `/etc/logrotate.d/kinstall-<product>-<instance>`，限制单盘占比 |
| 运行时目录 | `/run/kinstall/<product>-<instance>/` | 由 systemd `RuntimeDirectory=` 自动创建 |
| 系统用户 | 专用无登录用户（如 `valkey`、`postgres`、`mysql`、`opensearch`），或按实例隔离 `ki-<product>-<instance>` | 禁止以 `root` 运行中间件主进程 |
| systemd Unit | `kinstall-<product>-<instance>[-<role>].service` | 统一加 `LimitNOFILE`、`OOMScoreAdjust=-900`（数据库/核心存储）、`Restart=on-failure`、`RestartSec=5s`；单主机多实例无 unit 名冲突 |
| Exporter Unit | `kinstall-<product>-<instance>-exporter.service` | 端口在 `HostRole.Claims` 登记 |
| 证书目录 | `/etc/kinstall/<product>/<instance>/pki/` | 复用平台 PKI，**每实例一个独立 CA**（防止跨实例证书混用） |

### 1.2 通用能力维度（对齐 `02 §3.7`）

1. **拓扑与角色**：每个插件在 `plugin.yaml` 中声明支持的 `topologies`（如 `standalone`、`primary-replica`、`cluster`）和节点 `roles`，并在 `Validate` 中检查最小节点数与反亲和故障域（`topology.kinstall.io/zone` / `rack`，`03 §1.5`）。
2. **Profile 与 HostRequirements**：插件声明所需主机初始化 Profile（`03 §6.1`：`cache`、`database-pg`、`database-mysql`、`search`、`object-storage`）及附加包/内核模块/端口；`Plan` 阶段自动检测主机是否已应用对应 Profile，未应用则阻断或自动编入前置初始化 Phase。
3. **HostRole.Claims**：安装前必须向 CMDB 登记全部监听端口（含客户端、复制/集群总线、管理、exporter）、目录、独占盘与预估内存/大页（`03 §8.5`），同主机端口冲突在 `Plan` 阶段即以 `KI-HOST-0002` 阻断。
4. **凭据与密钥**：禁止用户把明文密码写入 `Spec`；安装时平台自动生成高强度随机密码写入 `SecretStore`（或引用已有 `{{ secret "..." }}`），经 `file.sync` / stdin 下发并记录审计。
5. **页大小校验（ADR-028）**：每个组件 BOM 必须标注 `pageSizes`，凡链接 4K-only `jemalloc` 的构建在 arm64 64K 页主机上 `Plan` 阶段直接阻断（`KI-PLAN-0012`）。

## 2. `host-binary` vs `host-container`（Docker）vs `kubernetes` 三元部署目标选择规则（F8、ADR-041 / ADR-066）

每个中间件插件声明支持的目标集合 `targets: [host-binary, host-container, kubernetes]`（ADR-066，详解见 `18 §2.1`）：

| 维度 | `host-binary`（二进制 / 上游包 + systemd） | `host-container`（Docker 29.10 + Compose v5.8 + systemd） | `kubernetes`（Operator / Helm v4） |
| --- | --- | --- | --- |
| 典型场景 | 尚无 K8s；超低延迟核心库（PG / MySQL / Kafka 大吞吐 Broker）；物理 NVMe / JBOD 直通；无 Docker 审批的高密环境 | **无 K8s 但需快速标准化交付 ELK / SkyWalking / Kafka / Redis**；**老旧 OS（glibc < 2.28 如 CentOS 7）绕过宿主机依赖限制**；单机多实例隔离 | 已有稳定生产 K8s（带高性能块/本地 NVMe CSI）；多租户自助化与统一 GitOps 运维 |
| 性能与隔离 | 零容器网络/存储叠加损耗；可绑定 NUMA、透明大页与静态大页 | 接近裸机（大流量有状态组件优先 `network_mode: host` + 宿主机 XFS bind-mount，仍须应用宿主机 Profile 如关 THP） | 接近裸机（Local PV + `Guaranteed` QoS + 独占污点节点） |
| 运维与安全治理 | 由 kinstall Operation 编排（Patroni / MGR / Sentinel / KRaft 负责运行期 HA） | 由 `compose.sync` 生成 `kinstall-compose-<inst>.service` 托管；**强制配置 `DOCKER-USER` 防火墙链**防止容器发布端口绕过 `ufw`/`firewalld` | 由成熟开源 Operator 负责运行期自愈、自动备份与滚动升级 |
| 离线与依赖 | 需注意 C/C++ 的 glibc 基线与 arm64 64K 页构建（ADR-068） | 离线推送多架构 OCI 镜像到 Zot 或 tarball 导入，彻底隔离宿主机库依赖 | 需离线化 Operator 镜像、组件镜像与 Helm Chart |
| **反选禁区** | glibc < 2.28 的老旧 OS 不推荐直跑现代 C++ 二进制（改用 `host-container`） | 不可将容器日志放任不限容（强制 `max-size`/`max-file`）；禁止把重要数据放在容器匿名卷 | **禁止**在无高可靠持久化 CSI 的 K8s 上跑单副本核心库；**禁止**依赖 Bitnami 公共镜像（ADR-042） |

## 3. Kubernetes Operator 选型总表（R-MW-06、ADR-042）

> **关键供应链警告（Bitnami 变更）**：Broadcom 于 2025-08-28 / 2025-09-29 将绝大多数免费版本化 Bitnami 容器镜像与 Helm Chart 迁入冻结且不再更新的 `bitnamilegacy` 仓库，生产版本转入收费订阅 **Bitnami Secure Images（BSI）**。因此 **kinstall 全平台禁止依赖 Bitnami 公共 Chart 或镜像**（ADR-042），所有 K8s 目标一律选用上游官方镜像与开源 Operator。

## 4. 统一运维操作语义（F9）

所有组件插件必须实现标准 `Operation` 名称及语义，使 CLI / REST API / 审批门 / 报告模板对全部中间件一致：

| Operation | 变更性 | 锁与并发 | 前置检查与语义 |
| --- | :---: | --- | --- |
| `install` | 写 | 实例排他 + 主机共享 | 应用 Profile → 分发制品 → 签发 CA/证书 → 写配置/systemd → 初始化集群 → 健康检查 → 登记 `InstalledFile` 与 `Claims` |
| `scale` | 写 | 实例排他 + 新增/移除主机共享 | 扩容按角色逐节点加入并等待数据同步；缩容必须先做数据迁移/摘流（如 ES 迁分片、Valkey 迁槽、PG 停复制），**禁止直接删节点导致丢数据** |
| `upgrade` | 写 | 实例排他 + `serial: true`（有状态角色） | 强校验允许升级路径（禁止跨大版本直接滚动）；强制先做逻辑/物理备份检查点；按“从节点 → 主节点（触发优雅 switchover）”滚动；每步通过健康探针 |
| `backup` | 读/元写 | 不阻塞业务（单实例同时仅 1 个备份任务） | 支持目标：`local` / `nfs` / `s3`（兼容 Garage/SeaweedFS/RustFS/Ceph RGW）；产出统一 `BackupRecord`（backupId、size、sha256、start/endTime、LSN/GTID/snapshotName、retention） |
| `restore` | 写（高危） | 实例排他 + **强制审批门** | 默认推荐“恢复到新实例”或演练实例；原地恢复须显式 `--in-place --confirm-name <inst>` 并先停应用写入；支持 PITR（`--target-time`）的组件需校验 WAL/binlog 连续性 |
| `reconfigure` | 写 | 实例排他 | 区分热更新（如 `CONFIG SET` / `ALTER SYSTEM` + `pg_reload_conf`）与需重启参数；需重启时按滚动策略与维护窗口执行 |
| `rotate-certs` | 写 | 实例排他 | 签发新证书 → 先追加信任新 CA → 滚动替换叶证书 → 移除旧 CA；保证零中断 |
| `failover` | 写 | 实例排他 | 计划内主从切换（switchover），验证目标副本复制延迟低于阈值后再切换 |
| `user` | 写 | 实例共享 | 账号创建、改密、授权、吊销；口令全部经 `SecretStore` 托管 |
| `uninstall` | 写（高危） | 实例排他 + **强制审批门** | 停服务、移除 systemd 与配置、按 `InstalledFile` 清理；**默认保留 `/data` 数据目录**，仅当传入 `--purge-data` 时擦除 |

## 5. 统一监控、告警与日志采集（F10、I2、ADR-043）

### 5.1 监控接入规范

- **host 模式**：每个中间件实例可选随装官方/主流 Prometheus Exporter（由 `kinstall-<product>-<instance>-exporter.service` 托管），只监听内网管理 IP + TLS/BasicAuth，通过文件服务发现（`file_sd_configs` JSON）或 HTTP SD 注册到客户已有 Prometheus / kube-prometheus-stack。
- **kubernetes 模式**：自动创建 `ServiceMonitor` / `PodMonitor` 与 `PrometheusRule`。
- **统一标签**：所有指标与告警规则强制附带 `kinstall_project`、`kinstall_env`、`kinstall_instance`、`kinstall_product`、`severity`（`critical` / `warning` / `info`）。
- **核心 Exporter 版本基线（截至 2026-11-26）**：

| 组件 | Exporter / 端点 | 版本 | 许可证 | 采集端口 |
| --- | --- | --- | --- | ---: |
| Valkey / Redis | `oliver006/redis_exporter` | **v1.99.0**（2026-11-24，支持 Valkey 9.x/8.x 与 Redis） | MIT | 9121 |
| PostgreSQL | `prometheus-community/postgres_exporter` | **v0.21.1**（2026-11-18） | Apache-2.0 | 9187 |
| MySQL | `prometheus/mysqld_exporter` | **v0.21.0**（2026-10-22） | Apache-2.0 | 9104 |
| Elasticsearch / OpenSearch | `prometheus-community/elasticsearch_exporter`（或 OpenSearch 内置 Prometheus 插件） | **v1.11.0**（2026-07-10） | Apache-2.0 | 9114 |
| 对象存储 | 原生 `/metrics`（Garage / SeaweedFS / RustFS / Ceph MGR prometheus 模块） | 随组件版本 | 同组件 | 见 `11 §10` |

### 5.2 日志采集选型（ADR-043）

> **重要上游变化**：Grafana **Promtail 已于 2026-03-02 正式 EOL**，不再维护。kinstall **不提供 Promtail 模板**。

- **host 模式日志转发**：默认仅落盘 + `logrotate`；若用户开启集中日志转发，提供两种轻量模板：
  1. **Fluent Bit**（CNCF Graduated，Apache-2.0，C 实现内存占用最低，推荐默认）；
  2. **Grafana Alloy**（`v1.22.0`，2026-11-13，Apache-2.0，OTel 原生，推荐给已使用 Grafana Loki / OTLP 生态的团队）或 **Vector**（MPL-2.0，Rust）。
- **禁止**默认打包 Elastic Filebeat（ELv2 许可限制再分发）。

## 6. 二期：声明式插件包格式（B7、ADR-044 / ADR-069）

声明式插件包（`02 §3.5`）无需重新编译 `kinstall` 主程序即可热扩展能力。按 **ADR-069（18 §2.4）** 工程边界：具复杂分布式共识与引导逻辑的核心产品（K8s、Valkey/Redis、PG、MySQL、OpenSearch/ELK、Kafka、SkyWalking、对象存储）采用强类型 Go 插件；**声明式插件包专用于无复杂共识的轻量组件及新版本配置/BOM 模板热扩展**。

### 6.1 插件包目录结构

```text
zookeeper-plugin-0.1.0/
├── plugin.yaml               # 插件元数据、支持产品/拓扑/平台/端口/SDK版本（02 §3.2）
├── schema/
│   └── params.json           # JSON Schema Draft 2020-12，CLI 校验 + Web UI 表单渲染
├── artifacts.yaml            # 产品版本 × 架构 × OS 制品、sha256、上游签名、pageSizes
├── defaults.yaml             # 默认参数（02 §13.1 优先级 1）
├── vars/os/<family>.yaml     # OS 族覆盖变量
├── host-requirements.yaml    # 静态 + expr 条件化的 HostRequirements 与 Claims
├── operations/
│   ├── install.yaml          # Phase / Task DAG 定义
│   ├── upgrade.yaml
│   ├── scale.yaml
│   ├── backup.yaml
│   ├── restore.yaml
│   ├── reconfigure.yaml
│   └── uninstall.yaml
├── templates/
│   └── <semver-range>/       # 按产品版本选择（02 §13.2），如 ">=9.0 <10.0"
├── alerts/
│   └── rules.yaml            # Prometheus 告警规则模板
└── testdata/
    └── golden/               # 插件自带 golden 测试用例，打包前由 kinstall plugin test 验证
```

### 6.2 Operation DSL（`operations/*.yaml`）

```yaml
apiVersion: kinstall.io/v1alpha1
kind: DeclarativeOperation
metadata:
  name: install
spec:
  mutating: true
  preflight:
    - name: check-quorum-odd
      when: "product == 'zookeeper'"
      assert: "len(hosts) >= 3 && len(hosts) % 2 == 1"
      errorCode: KI-PLAN-0020
  phases:
    - name: install-binary
      hosts: { roles: [server] }
      concurrency: 10
      tasks:
        - uses: cmd.run
          with: { script: "useradd --system --no-create-home --shell /sbin/nologin zookeeper", checkCmd: "id -u zookeeper >/dev/null 2>&1" }
        - uses: binary.install
          with: { name: zookeeper, version: "{{ .Version }}", artifact: zookeeper-tarball }
        - uses: template.render
          with:
            dst: "/etc/kinstall/zookeeper/{{ .Instance.Name }}/zoo.cfg"
            template: "zoo.cfg.tmpl"
            mode: "0640"
            owner: "root:zookeeper"
          notify: [restart-zookeeper]
        - uses: systemd.unit
          with: { name: "kinstall-zookeeper-{{ .Instance.Name }}.service", template: "zookeeper.service.tmpl", enable: true }
      handlers:
        - name: restart-zookeeper
          uses: systemd.unit
          with: { name: "kinstall-zookeeper-{{ .Instance.Name }}.service", state: restarted }
```

**安全沙箱约束（ADR-044）**：
- `uses:` 仅允许调用平台内置 Task 库（`02 §3.4`）；
- 模板仅使用 `text/template` + 白名单函数（`02 §13.2`）；`when` / `assert` 仅使用预编译 `expr`（无 I/O、无副作用）；
- 导入插件包时执行静态校验（schema、expr 编译、模板语法、semver 区间无重叠无空洞、禁止未声明的 Task）。

### 6.3 OCI 打包、签名与仓库分发

- **打包格式**：使用 `oras-go/v3`（v3.0.0）打成标准 OCI Artifact：
  - `artifactType`: `application/vnd.kinstall.plugin.v1+tar+zstd`
  - 推送到内置 Zot（`12 §5`）或任意 OCI 仓库，离线环境以 `oci-layout` 目录或 `.tar.zst` 文件导入。
- **签名与校验**：发布者使用 `cosign sign`（或离线私钥）签名 OCI digest；`kinstall plugin install <ref>` 默认强制经 `sigstore-go v1.4.1` 验签，跳过须 `--insecure-skip-verify` 并记录审计事件 `security.signature_skipped`。
- **升级与回滚**：插件按 `name@version` 并存安装；已有 Instance 显式执行升级切到新插件版本并触发 `StateMigrator`（`05 §7.5`）。

## 7. 三期：gRPC 外部插件协议（B7、R-PLAT-01、R-REF-04）

### 7.1 外部参考调研结论（R-REF-04）

| 参考对象 | 关键可借鉴设计 | 不照搬之处 |
| --- | --- | --- |
| **Terraform Provider Protocol**（`hashicorp/go-plugin`） | 进程隔离、基于环境变量的 Magic Cookie 握手、协议主版本协商（v5/v6）、`Validate → Plan → Apply` 清晰契约、日志回流 | Terraform 面向云 API CRUD，状态模型与主机多步编排不同 |
| **KubeKey v4**（`v4.0.10`，2026-11-13） | Pipeline / Playbook 声明式编排、可插拔任务模块、K8s 与主机统一抽象 | 强绑定 Ansible/Playbook 风格，不契合 kinstall 的强类型 `TaskSpec` + CMDB |
| **Helm v4 Wasm 插件** | 跨平台单产物、沙箱强 | Wasm 生态在复杂存储/网络协议 SDK 上仍受限，留作远期选项 |

### 7.2 协议设计（`hashicorp/go-plugin` v1.8.0）

> 注：此处 gRPC 仅用于部署机本机主进程与外部插件子进程间通信（Unix Domain Socket / loopback），与 ADR-021（平台对外 API 一期无 gRPC）无冲突。

- **握手与协商**：`MagicCookieKey: "KINSTALL_PLUGIN_MAGIC"`；支持协议版本 `VersionedPlugins: { 1: ... }`；启动时主进程校验插件二进制 SHA-256 与 cosign 签名，设置最小环境变量（不透传主密钥与全量凭据）。
- **核心 Proto 服务（`kinstall.plugin.v1.ComponentService`）**：

```protobuf
service ComponentService {
  rpc GetMeta(Empty) returns (PluginMeta);
  rpc Validate(ValidateRequest) returns (ValidationReport);
  rpc Plan(PlanRequest) returns (PlanResult);
  rpc BuildPipeline(OpRequest) returns (PipelineSpec); // 返回声明式 Task DAG，插件自身不执行 SSH（ADR-003）
  rpc InspectStatus(StatusRequest) returns (InstanceStatus);
  rpc MigrateState(MigrateStateRequest) returns (MigrateStateResponse);
}
```

- **权限隔离原则**：外部插件进程**永不接触目标主机 SSH 连接与 Secret 明文**，只接收脱敏后的 Facts 视图、Spec 与 `secretRef`，返回 `PipelineSpec` 交给主进程的 Task Engine 执行；进程超时由主进程强杀并回收。
