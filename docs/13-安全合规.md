# 13 安全与合规（等保 2.0 / 密评映射与国密边界）

> **本文定位**：汇总 kinstall 平台自身安全架构、威胁模型、网络安全等级保护 2.0（GB/T 22239-2019）三级与商用密码应用安全性评估（密评，GB/T 39786-2021）控制项映射、国密支持边界与合规证据包规范。主机侧加固细节见 `03 §9`，K8s 安全基线见 `04 §14`，凭据信封加密实现见 `05 §5.5`。
>
> **版本**：v1.1（S14/V，2026-11-26；v1.1 补齐 `viewer` 角色、对齐 `G1 §5` 审计双链独立规范串、明确 SM3 链 + 定期 SM2 锚点及 `--standard` 逗号分隔语法）。标准现状、工具与密码库版本截至 2026-11-26，引用前请复核。

## 1. 定位与合规声明

- **合规边界**：合规（等保测评、密评）是对**客户整体信息系统**（物理机房 + 网络边界 + 主机 + 平台 + 业务 + 管理制度）的评估，任何安装工具本身都不能宣称“自动通过等保/密评”。
- **kinstall 的职责**：①保障平台自身达到金融/政务安全基线；②提供可复现、可审计的主机与集群安全基线配置；③通过 `kinstall compliance report` 自动化产出测评所需的配置核验、补丁/漏洞扫描、日志留存与操作审计**证据包**，大幅降低客户整改与迎检成本。

### 3.1 K8s 安全基线与运行时安全（补充）

- **CIS Kubernetes Benchmark 与 `kube-bench`**：截至 2026-11，行业主流采用 **CIS Kubernetes Benchmark `v1.12`**（覆盖 1.32–1.36；**CIS `v2.0.0`** 正在推进适配 1.34–1.35+）；kinstall 集成 **`kube-bench v0.16.0`**（2026-08-05）作为合规检查命令，并为二进制部署路径提供专用配置文件覆盖（规避默认假定 kubeadm 路径的误报）。
- **容器运行时安全（可选 Addon）**：
  - **Cilium Tetragon `v1.8.0`**（2026-10-30，Apache-2.0，CNCF）：内核级 eBPF 观测与**内核态实时阻断**（`TracingPolicy`），当集群采用 Cilium CNI 时原生契合，推荐默认；
  - **Falco `0.40+`**（CNCF Graduated，Apache-2.0）：modern eBPF 驱动，成熟威胁检测规则库，适合以告警审计为主的集群。

## 4. 密评（GB/T 39786-2021）与国密支持边界（H4、R-SEC-05、ADR-060 / ADR-061）

### 4.1 技术现状核实（截至 2026-11-26）

1. **Go 标准库（Go 1.27.4）与上游 Kubernetes（1.35–1.38）**：仍**不支持** SM2 / SM3 / SM4 及 TLCP（GB/T 38636）国密 SSL 协议；强行魔改 K8s / containerd / etcd 源码会导致丧失上游安全补丁能力且无法通过一致性认证。
2. **Go 纯国密算法库**：
   - **`github.com/emmansun/gmsm` `v0.45.4`**（2026-11-20 发布，MIT）：持续活跃维护、纯 Go 实现（兼容 `CGO_ENABLED=0`）、支持 SM2/SM3/SM4-GCM 及 amd64/arm64 汇编加速；
   - **`github.com/tjfoc/gmsm` `v1.4.1`**（停更于 2021-07-09，逾 5 年无维护）：**正式禁止使用**。
3. **国密 TLS 密码库**：OpenAtom 基金会 **铜锁 / Tongsuo**（2026-03 发布 `8.5.0-pre1`；提供完整 TLCP 双证书支持，但注意主流 OS 默认仓库不预装 Tongsuo，需独立打包 Nginx/Envoy 国密反代镜像）。

### 4.2 国密支持边界决策（ADR-060 / ADR-061）

- **明确原则（ADR-060）**：**K8s 集群内部与各开源中间件内部保持标准国际密码算法（TLS 1.3 + ECDSA-P256 / AES-256-GCM），绝不魔改上游二进制；密评要求通过“平台可选国密存储 + 外围国密网关 + 硬件密码机对接 + 风险缓解说明”四层落地**：
  1. **网络与通信层面**：在 kinstall Server Web/API 与集群南北向入口前置支持 **TLCP（GB/T 38636）的国密 SSL 网关**（商密认证硬件 SSL VPN/网关，或基于 OpenAtom **Tongsuo** 编译的双证书反代网关，满足浏览器/管理终端到平台的国密通信）；管理通道通过客户**国密堡垒机**进入受控运维区；
  2. **设备与计算层面**：SSH 协议本身（OpenSSH 上游）不支持国密算法，在密评中以“受控隔离运维网段 + 国密堡垒机接入 + 硬件密码机/UKey 双因素登录堡垒机”作为标准弥补措施；
  3. **应用与数据层面（ADR-061）**：kinstall 凭据库信封加密通过 `KEKProvider` / 算法接口原生支持可选 **SM4-GCM**（采用纯 Go `emmansun/gmsm v0.45.4`）与 **KMIP / 厂商硬件密码机（HSM/云服务器密码机）对接**，满足重要凭据与密钥存储的商用密码合规；
  4. **完整性与供应链**：离线 Bundle 支持 `cosign` + **SM2/SM3 双签**（`manifest.json.sm2sig`，`D3 §1.3`）；平台审计日志开启国密模式后并行写入**独立 SM3 哈希链** + 定期 SM2 签名锚点（每小时或每 10,000 条记录锚定），兼顾国际工具链与国内密评验收。

### 4.3 密评四层面 × kinstall 支撑矩阵

| 密评层面（GB/T 39786 三级） | 核心要求 | kinstall 支撑方案 | 需客户侧配套硬件/资质 |
| --- | --- | --- | --- |
| 物理与环境安全 | 机房门禁/视频加密 | 不涉及（基础设施层） | 机房国密门禁与电子门禁记录完整性 |
| 网络与通信安全 | 通信实体身份鉴别、重要数据机密性/完整性 | 外围前置国密 SSL 网关（TLCP）；内部受控区 TLS 1.3；导出网关配置证据 | 获商密型号证书的 SSL VPN / 国密网关 |
| 设备与计算安全 | 远程管理通道安全、重要可执行程序完整性 | 管理入口经国密堡垒机；Bundle 与二进制支持 SM2/SM3 双签校验；KYSEC/fapolicyd 配合可信启动 | 商密认证堡垒机、可信计算芯片（TCM/TPM） |
| 应用与数据安全 | 鉴别信息与重要业务数据存储加密、不可否认性 | 平台凭据库可选 SM4-GCM（`emmansun/gmsm`）或对接硬件 KMS/HSM；K8s etcd 对接支持国密后端的 KMS v2 插件；审计日志 SM3 哈希链 | 获商密型号证书的服务器密码机（HSM）与电子签章/CA |

## 5. 平台自身安全加固补充（ADR-062）

- **审计日志防篡改（ADR-062）**：`audit_logs` 每行按固定列序覆盖除哈希列外的全部业务列分别独立计算双链：`record_sha256 = SHA256(prev_sha256|seq|RFC3339Nano|actor_id|actor_type|source_ip|project_id|action|target_type|target_id|result|err_code|trace_id|SHA256(payload))`；国密模式并行独立计算 `record_sm3 = SM3(prev_sm3|seq|RFC3339Nano|...|SM3(payload))`（不依赖 SHA-256 字段，详见 `G1 §5.2`）；提供 `kinstall audit verify` 离线校验链条连续性，并支持实时通过 TLS syslog（RFC 5425）或 OTLP 外送至外部不可变存储（WORM），确保本地被攻破后无法悄然抹除痕迹。
- **备份与快照加密**：平台数据库自动备份在落盘前复用信封加密或用户指定加密口令加密；恢复时强制校验签名与完整性。
- **最小攻击面**：Server 模式启用安全响应头（CSP、HSTS、`X-Frame-Options: DENY`）、API 速率限制、单 IP 登录暴力破解锁定、Web 静态资源全部内嵌且无外链 CDN。

## 6. 安全测试与漏洞响应

| 类别 | 工具 / 方法 | 执行频率 | 门禁 |
| --- | --- | --- | --- |
| SAST（静态分析） | `gosec`（via golangci-lint）、CodeQL | 每次 PR | High 阻断 |
| SCA（依赖与二进制漏洞） | `govulncheck` + Syft + Grype（`12 §8`） | 每次 PR + 每日 | Critical 可达阻断 |
| 密钥防泄露 | `gitleaks`（pre-commit + CI） | 每次提交 | 零容忍阻断 |
| DAST / API 模糊测试 | Go 原生 `go test -fuzz`（解析器/模板/osmatch）+ OWASP ZAP 扫描 `/api/v1` | 每周 / 发版前 | High/Critical 阻断 |
| 渗透测试清单 | 认证绕过、跨项目 IDOR、审批门自审绕过、模板注入（SSTI）、命令注入（`shellescape` 复核）、路径穿越（Tar Slip） | 每个主/次版本发布前 | 全部修复复测 |

**CVE 响应 SLA**：收到安全报告后 24 h 内确认；Critical 漏洞 72 h 内发布补丁版本或新 BOM revision + 安全公告（CSAF / GitHub Security Advisory）；High 漏洞 7 天内修复。

## 7. 合规报告与证据包（`kinstall compliance report`）

`kinstall compliance report --standard mlps3,cis,gm --scope <project|instance> --output evidence-2026-11.tar.gz`（`--standard` 逗号分隔可多选，与 `G2 §4` 一致） 产出标准化证据目录：

```text
evidence-2026-11.tar.gz
├── summary.md                 # 面向测评师的总览报告（通过/部分满足/需客户补充统计）

├── host-harden/               # 各主机 03 §9 verify 报告与漂移检查结果

```

## 8. 风险与待办

- 若未来全国网安标委发布 GB/T 22239 新修订版，需按条款变更对照更新 `compliance report` 映射模板；
- 国产硬件密码机厂商接口差异大（SDF / PKCS#11 / KMIP），三期需以独立外部插件（`06 §7`）接入具体厂商 SDK，防止污染主程序 `CGO_ENABLED=0` 构建。

## 附 A. 本文涉及的决策与清单映射

- **新增 ADR**：
  - **ADR-060**：国密支持边界——K8s 集群与中间件内部坚持标准国际密码算法不魔改上游源码；密评通过外围国密 SSL 网关（TLCP/Tongsuo）、国密堡垒机、平台凭据库可选 SM4/HSM 以及制品 SM2/SM3 双签组合满足（13 §4）。

- **关闭设计项**：H3、H4。
- **关闭调研项**：R-SEC-05、R-SEC-06。
