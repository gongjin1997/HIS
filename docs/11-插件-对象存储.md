# 11 插件设计：对象存储（MinIO 替代选型与插件设计）

> **本文定位**：完成 MinIO 社区版归档后的对象存储替代选型（定稿 ADR-012），并给出 kinstall 对象存储插件的分层架构与实现规范（为 K8s 备份、PostgreSQL pgBackRest、MySQL XtraBackup、OpenSearch 快照、平台日志与业务数据提供 S3 兼容存储）。通用约定遵循「06 中间件插件通用规范」。
>
> **版本**：v1.1（S12/V，2026-11-26；v1.1 对齐 Garage AGPL 红灯不入公共包、多 Filer 禁单机 LevelDB 及 `kinstall-object-storage-*` unit 命名）。版本号、项目状态与许可证信息截至 2026-11-26，引用前请复核。

## 1. 定位、背景与选型结论（F3、R-MW-02、ADR-012 定稿、ADR-054～056）

### 1.1 MinIO 社区版现状（已淘汰）

- 2025-10：MinIO 社区版停止发布预编译二进制，仅提供源码；
- 2025-12：进入维护模式，移除了 Web Console 大部分管理功能；
- 2026-02 / 2026-04-25：GitHub `minio/minio` 仓库正式归档；2026-09 Docker Hub 社区镜像下线；
- 官方全面转向商业产品 **AIStor**（AIStor Free 有非生产/单节点/商业许可限制）。
- **结论（ADR-012 定稿）**：**禁止在 kinstall 中将 MinIO 社区版作为默认或推荐方案**；第三方社区分支（`pgsty/minio`、SILO）因长期安全维护人数有限且仍受 AGPLv3 约束，亦不列为默认，仅允许迁移期只读对接既有 MinIO 桶。

### 1.2 选型结论摘要（ADR-054）

没有单一项目同时完美覆盖“轻量单机备份”与“PB 级多租户企业对象存储”，kinstall 对象存储插件采取**单插件多引擎分层选型**：

| 档位 | 推荐引擎 | 版本（2026-11） | 许可证 | 适用场景 |
| --- | --- | --- | --- | --- |
| **默认通用引擎** | **SeaweedFS** | `4.54`（活跃日更） | **Apache-2.0** | 中小至中大规模（1 TB～数百 TB）独立对象存储、离线备份目标、同时需要 S3 + POSIX/WebDAV；Go 单二进制，amd64/arm64 零依赖，Apache-2.0 许可干净 |
| **大规模 / K8s 统一存储** | **Ceph RGW**（经 Rook-Ceph 或 cephadm） | Ceph（随 Rook `v1.21.3`） | LGPL-2.1/3.0 | > 100 TB 企业级、多站点双活、强合规（完整 IAM/STS/Object Lock/审计）；若 K8s 已按 `04 §7` 部署 Rook-Ceph，直接开启 `CephObjectStore` 零额外基础设施 |
| **可选轻量引擎（观察/晋升候选）** | **RustFS** | `1.0.6`（2026-09 GA） | **Apache-2.0** | 强需求“MinIO 对等体验”（9000/9001 端口、纠删码、AWS IAM 策略、内置 Console）且可接受 1.0 新兴项目的场景；通过 12 个月生产浸泡后评估是否晋升并列默认 |
| **可选边缘/多点引擎** | **Garage** | `v2.5.0` | AGPLv3 | 边缘/多机房弱网同步、极低内存占用（< 100 MiB）；**注意**缺少完整 IAM 策略与 Object Lock，且受 AGPLv3 约束 |

## 2. 候选方案全面对比与加权评分（R-MW-02）

| 评估维度（权重） | **SeaweedFS 4.54** | **Ceph RGW** | **RustFS 1.0.6** | **Garage v2.5.0** | MinIO 社区分支 |
| --- | :---: | :---: | :---: | :---: | :---: |
| 许可证友好度（20%） | Apache-2.0（5） | LGPL（4） | Apache-2.0（5） | AGPLv3（2） | AGPLv3（2） |
| 生产成熟度与社区（25%） | >10 年，极其活跃（4.5） | 行业标杆（5） | 2026-09 刚 1.0 GA（3） | 中小规模稳定（4） | 维护不确定（2） |
| S3 特性完备度（20%） | 版本/生命周期/IAM/Object Lock/SSE（4.5） | 完备（IAM/STS/WORM/多活）（5） | 接近 MinIO（IAM/EC/Console）（4.5） | 子集（无完整 IAM/Object Lock）（3） | 完备（4.5） |
| 离线与部署复杂度（20%） | 单 Go 二进制，中低（4.5） | 重（≥3 节点 + 独占 OSD）（2.5） | 单 Rust 二进制，低（5） | 单 Rust 二进制，极低（5） | 单二进制（4） |
| 资源占用与 arm64（15%） | 中低，amd64/arm64 完好（4.5） | 较高（3） | 极低、高性能（5） | 极低（5） | 低（4） |
| **加权总分（满分 5）** | **4.60（默认）** | **4.03（大规模/K8s）** | **4.35（观察可选）** | **3.75（边缘可选）** | **3.15（不采纳）** |

- **关于 AGPLv3 对 kinstall 的影响（A5、ADR-059）**：kinstall 仅通过外部进程编排，不链接其代码；按 `D3 §6.3` 红灯许可策略，**Garage（AGPLv3）不随 kinstall 公共离线包分发**，由客户确认条款后按需自建。SeaweedFS 与 RustFS 均为 Apache-2.0，可直接打入公共离线包。

## 4. 拓扑与角色（以默认引擎 SeaweedFS 为主，兼顾 RustFS / Ceph RGW）

| 引擎 | 拓扑 | 角色与节点数 | 容错与数据冗余 |
| --- | --- | --- | --- |
| **SeaweedFS** | `standalone` | 1 台（`weed server` 单进程） | 开发测试（无副本） |
| **SeaweedFS** | `ha-replicated` | 3 台 `master` + ≥ 3 台 `volume`（每台多块 JBOD 盘）+ 2 台 `filer`（多 Filer 生产必须接外部 `08` PostgreSQL / Valkey 或 Raft 元数据组；单机/单 Filer 开发测试方可使用嵌入式 LevelDB）+ 2 台 `s3` 网关（前置 LB） | 默认副本 `001`（跨机架 `010` / 跨可用区 `100`）；大文件热转冷可启用内置 **Reed-Solomon 10+4 纠删码**（空间利用率 71%，容忍 4 盘故障） |
| **RustFS** | `distributed-ec` | ≥ 4 台 × ≥ 4 块 JBOD 盘（共 ≥ 16 盘） | 原生纠删码（默认 EC:4 容忍 N/2 盘故障，单节点可宕） |
| **Ceph RGW** | `rook-objectstore` / `cephadm` | ≥ 3 台（MON/MGR/OSD/RGW） | 副本 3 或 EC `4+2` / `8+3`，支持多站点主动复制 |

## 5. 部署目标：`host` vs `kubernetes`

- **`host` 模式（默认）**：物理机/VM 直连多块本地 JBOD 磁盘（**禁止硬件 RAID 叠软件纠删码**，直接 JBOD 独立挂载 `/data/object-storage/<instance>/disk{1..N}`，XFS `noatime,nodiratime`），systemd unit 命名 `kinstall-object-storage-<instance>-{master,volume,filer,s3}.service`（与 `product: object-storage` 及 `06 §1.1` 对齐）。
- **`kubernetes` 模式**：
  - 若集群已部署 Rook-Ceph（`04 §7`），直接声明 `CephObjectStore` CR 提供 Ceph RGW S3 端点（**推荐**，与块/文件存储共享底层 OSD 池）；
  - 独立轻量场景通过 Helm v4 SDK 部署 SeaweedFS 官方 Chart（Apache-2.0），挂载 Local PV。

## 6. 主机要求与容量声明

- **Profile**：`base` + `object-storage`（`03 §6.1`）。
- **`HostRequirements`**：
  - `sysctl`：`net.core.rmem_max = 16777216`、`net.core.wmem_max = 16777216`、`net.ipv4.tcp_tw_reuse = 1`、`net.core.somaxconn = 65535`、`vm.dirty_ratio = 20`；
  - `limits`：`nofile >= 131072`；
  - 磁盘：通过 `03 §6.10` `disk` 模块逐块格式化 XFS 并按 UUID 挂载，禁用硬 RAID 缓存策略隐患；
  - 端口放行（SeaweedFS）：Master `9333/19333`、Volume `8080/18080`、Filer `8888/18888`、S3 API `8333`（建议前置 LB 统一暴露 `443` / `9000`）、Metrics `9324`。
- **`HostRole.Claims`**：独占全部 JBOD 数据盘（禁止与其他中间件共享盘）、端口、内存（SeaweedFS Filer/Volume 按磁盘块数每百万对象预留约 200 MiB）。

## 7. 安装流程（SeaweedFS `ha-replicated` `install` Pipeline）

| 顺序 | Phase | 目标角色 | 核心 Task | 并发 | 失败策略 | 幂等判据 |
| :---: | --- | --- | --- | :---: | --- | --- |
| 1 | `preflight` | 全部 | Profile `object-storage`、多块数据盘未占用且 XFS 挂载、时钟同步、Claims | 并行 10 | `failFast` | 只读 |
| 2 | `pki` | 本地 | 实例独立 CA；签发 gRPC 内部 mTLS 证书（`security.toml`）与 S3 HTTPS 证书 | 本地 | `failFast` | 证书指纹 |
| 3 | `install-bin` | 全部 | `user.ensure(seaweedfs)`、`binary.install(weed)`、`exec.allowlist` | 并行 10 | `failFast` | 版本软链 |
| 4 | `start-master` | `master` | `file.sync(master.toml, security.toml, unit)`、启动 3 节点 Master Raft 仲裁、`wait.http(:9333/cluster/status)` | 并行 3 | `failFast` | Raft Leader 选出 |
| 5 | `start-volume` | `volume` | `file.sync(volume unit)`（按机架/可用区注入 `-dataCenter`/`-rack`）、启动全部 Volume 节点 | 并行 10 | `failFast` | `/dir/status` 全部磁盘在线 |
| 6 | `start-filer-s3` | `filer` / `s3` | 配置 Filer 存储后端（多 Filer 生产强制外部 PG/Valkey 或 Raft 元数据组；仅单 Filer 开发模式可用嵌入式 LevelDB）、写 S3 IAM 初始管理员凭据（`SecretStore`）、启动 Filer 与 S3 网关 | 并行 10 | `failFast` | S3 `ListBuckets` 200 |
| 7 | `verify` | 本地 | 使用 AWS S3 v4 签名客户端建探针桶、上传/校验 ETag/下载/开启版本与 Object Lock/删除、验证 `/metrics` 200 | 本地 | `failFast` | 探针通过 |

## 8. 配置、纠删码与安全设计（ADR-055 / ADR-056）

- **数据可靠性策略（ADR-055）**：
  - 写入期使用跨故障域副本（`010` 跨机架或 `100` 跨可用区），保证低写延迟；
  - 后台 `weed shell` 定时任务（`ec.encode -quietFor=24h`）将静默冷卷自动转换为 **Reed-Solomon 10+4 纠删码**（仅需 1.4× 原始空间），兼顾热写速度与冷存成本。
- **全链路加密与 IAM（ADR-056）**：
  - 强制开启 S3 HTTPS（TLS 1.2/1.3）与组件间 gRPC mTLS（`security.toml` 配置 `jwt.signing` + TLS 证书）；
  - 服务端静态加密支持 **SSE-S3**（由平台生成/托管主密钥或对接 OpenBao KMS，复用 `05 §5.5`）与 **SSE-C**；
  - 为每个上层消费插件（如 `pg-backup`、`es-snapshot`、`k8s-velero`）自动创建独立桶与最小权限 IAM AccessKey/SecretKey（按桶前缀隔离，禁用跨桶访问），凭据全部存 `SecretStore`；
  - 合规归档桶支持开启 **S3 Object Lock（WORM）** 防勒索软件篡改备份。

## 9. 运维操作

| 操作 | 实现要点 |
| --- | --- |
| `scale` | Volume 节点水平扩容直接加入并执行 `volume.balance` 自动均衡数据；缩容前执行 `volume.fix.replication` 与 `volume.move` 迁空待退盘数据 |
| `upgrade` | `serial: true` 逐节点升级二进制：先升级 `s3` → `filer` → `volume`（确认每卷副本健康）→ 非 Leader `master` → Leader `master` |
| `backup` / 复制 | 对象存储本身常作备份目标；跨机房灾备通过 `weed filer.backup` / S3 Bucket Async Replication 异步复制到异地集群 |
| `reconfigure` | 桶配额、生命周期过期规则（自动清理 30/90 天历史备份）、IAM 账号策略均通过 `weed shell` / IAM API 热更新，无需重启 |
| 故障盘替换 | 更换坏盘后挂载新 XFS 盘重启该 Volume，执行 `volume.fix.replication` / `ec.rebuild` 自动重建缺失副本或纠删分片 |

## 10. 监控、日志与告警规则

SeaweedFS、RustFS、Garage、Ceph RGW 均原生暴露 Prometheus `/metrics`（SeaweedFS 启动参数 `-metricsPort=9324`），无需额外第三方 exporter：

```yaml
groups:
  - name: kinstall.object_storage
    rules:
      - alert: ObjectStorageEndpointDown
        expr: up{job=~"kinstall-object-storage.*"} == 0
        for: 1m
        labels: { severity: critical }
      - alert: SeaweedFSVolumeDiskUsageHigh
        expr: (SeaweedFS_volumeServer_total_disk_size - SeaweedFS_volumeServer_free_disk_size) / SeaweedFS_volumeServer_total_disk_size > 0.80
        for: 10m
        labels: { severity: warning }
      - alert: SeaweedFSReadOnlyVolumes
        expr: SeaweedFS_volumeServer_volumes{type="readOnly"} > 0
        for: 5m
        labels: { severity: warning }
      - alert: SeaweedFSS3ErrorRateHigh
        expr: sum(rate(SeaweedFS_s3_request_total{code=~"5.."}[5m])) / clamp_min(sum(rate(SeaweedFS_s3_request_total[5m])), 1) > 0.01
        for: 5m
        labels: { severity: critical }
```

## 11. 测试与验收

1. **S3 兼容互操作测试**：对接 `aws-cli`、`mc`（仅作客户端）、`pgBackRest 2.60`、`OpenSearch S3 snapshot`、`Velero` 跑通上传、分片上传（Multipart > 5 GiB）、版本控制、生命周期过期、Object Lock；
2. **故障注入**：在持续 S3 读写下拔除/卸载 1 块数据盘与强杀 1 台 Volume 节点，验证读写无中断且修复后副本/EC 分片恢复完整；
3. **性能基线**：使用 `warp` / `s3-benchmark` 测 1 MiB 小对象与 64 MiB 大对象读写吞吐与 P99 延迟。

## 12. 风险与待办

- RustFS 1.0 于 2026-09 刚 GA，需持续观察其在高并发小对象与纠删码重建中的稳定性，待 12 个月生产反馈后再决定是否提升为默认候选；
- SeaweedFS Filer 元数据在高对象数（> 1 亿）场景建议使用外部 PostgreSQL（`08`）替代嵌入式 LevelDB，规划阶段需根据对象量级自动提醒。

## 附 A. 本文涉及的决策与清单映射

- **ADR-012 定稿（状态改为“已采纳”）**：因 MinIO 社区版已于 2026-04 归档、公共镜像下线且官方转向商业 AIStor，kinstall 正式放弃 MinIO 社区版；采用分层对象存储选型——中小至中大规模通用默认 **SeaweedFS 4.54（Apache-2.0）**，大规模（> 100 TB）或 K8s 统一存储采用 **Ceph RGW（Rook v1.21.3 / cephadm）**，**RustFS 1.0.6（Apache-2.0）** 与 **Garage v2.5.0（AGPLv3）** 列为可选引擎。
- **新增 ADR**：
  - **ADR-054**：对象存储插件采用“单插件多引擎”抽象（默认 SeaweedFS，大规模/K8s 可切 Ceph RGW，可选 RustFS/Garage），统一向上层插件暴露标准 S3 端点与每消费方独立 IAM 桶凭据（11 §1、§2）。
  - **ADR-055**：SeaweedFS 生产默认“热写跨故障域副本 + 冷卷后台转 Reed-Solomon 10+4 纠删码”，物理机采用 JBOD 独立 XFS 盘，禁止硬件 RAID 叠软件纠删码（11 §6、§8）。
  - **ADR-056**：对象存储强制全链路 TLS（S3 HTTPS + 内部 gRPC mTLS），默认开启 SSE-S3 服务端加密并为备份桶支持 Object Lock（WORM）防勒索篡改（11 §8）。
- **关闭设计项**：F3。
- **关闭调研项**：R-MW-02。
