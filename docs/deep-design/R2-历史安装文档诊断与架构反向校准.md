## 3. 从真实业务现场反哺的 7 项 kinstall 架构增强（立即落地）

这份文档清晰展示了中国企业级项目（如 HZERO + HAIP/AIGC + DevOps 交付）的真实面貌，由此反推出 **7 项必须立即吸收的架构级增强**：

### 增强 1：全局 `registryMirror` 镜像自动重写引擎（并入 D2 `compose.sync`/`image.load` 与 D3 离线供应链）
- 插件模板中**永远只声明标准逻辑镜像引用**（如 `apache/rocketmq:5.5.1` + BOM 锁定的 `sha256:...`）；
- 在 Project / Environment 级别配置 `artifactSource.registryPrefix`（例如离线内置 Zot `10.0.0.10:5000/kinstall` 或客户私有 Harbor `harbor.corp.local/infra`），由底座渲染引擎在执行 `image.load` / `compose.sync` / `helm.release` 时**自动重写镜像前缀**并同步注入目标 `daemon.json` 私有 CA 信任（告别不安全的 `insecure-registries` HTTP 明文推拉！）。

### 增强 2：Docker Bridge 子网 IPAM 分配器与冲突防撞（立即回写 D2 DDL 与 `compose.sync`）
- 原文档为每个 Compose 服务手工划了 `10.20.101.0/24`、`10.20.103.0/24`、`10.20.104.0/24`、`10.20.112.0/24`——这是极真实的生产刚需（Docker 默认 `172.17-31.0.0/16` 极易与企业内网 `172.16.0.0/12` 冲突导致容器/宿主机路由黑洞！）。
- **底座增强**：
  1. D2 `instance_host_claims` 新增 **`subnets_json`** 字段，在 Plan 期同时检测同机 **端口、数据目录、Docker Bridge 子网** 三维零冲突，并校验不与主机真实路由表（D1 `NICS` Facts）及 K8s Pod/Service CIDR 重叠；
  2. 项目级配置默认 `dockerSubnetPool`（如 `10.240.0.0/16`，按 `/24` 自动顺序分配），也支持用户在 Instance Spec 显式指定自定义子网。

### 增强 3：多版本 JDK 共存与构建工具链隔离方案（并入 D3 底座 `runtime/*` 规范）
- 彻底满足“**同一台 CI 机上 Jenkins 跑 JDK 21、Maven 切 JDK 8/17/21 编译不同老/新项目、Node.js 多 LTS 并存**”的真实诉求：
  - 二进制目录：`/opt/kinstall/runtimes/jdk/{8,17,21,25}`、`/opt/kinstall/runtimes/maven/{3.9,3.10}`、`/opt/kinstall/runtimes/node/{22,24,26}`；
  - Maven 通过受管 `/etc/kinstall/maven/mavenrc` 或 Jenkins Tool Configuration（JCasC）声明绑定指定 JDK，**绝不修改 `$MAVEN_HOME/bin/mvn` 原文件**；
  - Jenkins 二进制部署模板自动通过 `pkg.ensure` 安装逻辑包 **`fontconfig` + `fonts-dejavu`**（解决原文档 L556 的无字体报错），并内置原文档验证的 **15 个常用中文企业级 Jenkins 插件离线清单**（简体中文包、Pipeline 全套、RBAC、ThinBackup、SonarQube Scanner、Webhook、ansiColor、Git）。

### 增强 4：新增 **Nginx L4(`stream`) + L7(`http/ws/tls`) 统一网关声明式包**
- 原文档 L900–1285 显示，企业内网交付极度依赖一台前置 Nginx 同时做：
  - **L7 HTTP/HTTPS + WebSocket 代理**（含 `client_max_body_size 4G`、TLS 1.2/1.3 强套件、HTTP→HTTPS 301 重定向、转发至 K8s NodePort 或业务容器）；
  - **L4 TCP `stream` 透传代理**（代理内网 MySQL `3306` / Redis `6379` 供跨网段研发/运维接入）。
- 新增声明式插件包 **`nginx-gateway`**（支持 `host-binary` 与 `host-container`），声明式定义 `httpRoutes`（域名/TLS/上游/WS/最大包体）与 `tcpStreams`（端口/白名单 CIDR/上游），下发前自动执行 **`nginx -t`** 语法验证失败即阻断，彻底消灭 `docker run nginxtest` → `docker cp` 的手工土办法。

### 增强 5：新增 **通用业务容器栈（`generic-app` 声明式模板，以 `hkms` 为样板）**
- 现场除了标准中间件，往往还要一并交付客户/厂商自研容器（如原文档中的 `hkms-python` AIGC 知识库，需同时连接 MinIO/S3、Milvus、MongoDB、Elasticsearch 和业务网关）。
- 通过 kinstall 的 **`Stack` + `generic-app` 声明式包**，客户无需写任何 Go 代码，只要写一份 YAML 引用 `${instances.s3.outputs.*}`、`${instances.milvus.outputs.*}`、`${instances.mongodb.outputs.*}`、`${instances.opensearch.outputs.*}`，即可把整套“中间件底座 + 业务应用容器 + Nginx 入口”作为单个 `Stack` 一键离线交付、3-Way Diff 巡检与统一备份！

### 增强 6：SonarQube / OnlyOffice / Milvus / Neo4j 现场细节修正（并入 P8 / P10）
- **SonarQube**：识别到客户强需求“社区版多分支扫描（`sonarqube-community-branch-plugin`）”，插件包支持通过声明式 `extraPlugins[]`（离线预打包 JAR + SHA-256）挂载至 `extensions/plugins` + `lib/common` 并自动注入正确的 `sonar.properties`（修复原文档拼写错），同时提示版本兼容性矩阵；
- **OnlyOffice**：明确区分为两个 Profile —— 默认推荐轻量 **`documentserver`（独立文档预览/编辑服务，占 95% 集成场景）**，完整 **`workspace`（含社区/邮件/控制面板全套）** 列为显式重型可选并禁用无保护的 `docker.sock` 裸露；内置中文字体包挂载目录 `/data/kinstall/onlyoffice/<inst>/fonts` 与自动刷字体缓存命令；强制 `JWT_ENABLED=true`；
- **Milvus**：默认同步提供可选伴生 UI **`Attu`**，默认改用非冲突端口（与 `P10 §1` 统一分配为 **`19001:3000`** 避开 SonarQube `9000`），保留 `seccomp:unconfined` 配置项并强制端口白名单保护 `9091`。

### 增强 7：补齐 **Zabbix 7.x LTS** 监控选项（原文档 L14 / L894 预留项）
- 对存量已建 Zabbix 运维体系的传统企业，提供两层轻量集成（不取代 kinstall 默认的 Prometheus/Grafana 体系）：
  - 主机初始化可选模块 `zabbix-agent2`（通过 `pkg.ensure` 或静态二进制部署并指向客户 Zabbix Server/Proxy）；
  - 声明式 OCI 插件包 `zabbix-server`（Zabbix `7.0/7.4 LTS` + `Stack` 复用 kinstall PostgreSQL 18 + TimescaleDB 扩展）。

## 4. 交付方式代际对比（`old-install.md` vs kinstall）

| 维度 | `old-install.md` 历史手工交付 | kinstall 自动化平台交付 |
| --- | --- | --- |
| **整套环境交付耗时** | 1–2 天（手工查错、改 IP/端口/密码、逐台敲命令） | **15–30 分钟**（单份 `Stack` YAML 一键离线编排） |
| **重复执行幂等性** | 无（重复 `cat >>` 导致 `/etc/sysctl.conf`、`/etc/profile` 无限追加垃圾行） | **100% 幂等 + 3-Way Diff**（二次执行全 `Skipped`，远端手改自动拦截） |
