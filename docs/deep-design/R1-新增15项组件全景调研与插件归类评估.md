# R1 扩展生态专题调研：15 项新增组件全景评估与 kinstall 插件归类方案

> **本文定位**：针对用户提出的 **15 项新增组件**（MongoDB、Rancher / Reranker、OnlyOffice、ZooKeeper、JDK 二进制安装、Harbor、GitLab、Jenkins、Maven、Npm/Node.js、SonarQube、Apache RocketMQ、Apache Seata、Milvus、Neo4j），逐项完成 **2026-11 联网实证调研**（最新稳定版本、许可证与合规红线、arm64 / 64K 页兼容性、高可用架构与离线生产坑），并给出在 kinstall「**先底座 → 再平台 → 再各插件**」架构中的精确落位与插件归类决策。
>
> **核验日期**：2026-11-26。

## 1. 15 项新增组件全景决策总表

为防核心平台失控膨胀，严格遵循 `ADR-059`（许可证分级）与 `ADR-069`（Go 插件 vs 声明式 OCI 包分工），将 15 项组件清晰归为四类：
- **① 底座运行时模块（`Runtime`）**：纯基础运行时/构建工具链二进制，被大量插件共用，作为平台底座通用包交付；
- **② 核心 Go 插件（`Go Plugin`）**：具复杂分布式共识/主从切主/数据盘/备份恢复协议，纳入核心 Go 插件矩阵；
- **③ 声明式 OCI 插件包（`Declarative OCI Pack`）**：无复杂底层共识或主要以容器/Helm/Omnibus 交付的应用层/DevOps 组件，用 YAML 声明式包 + 15 个内置 Task 零代码接入；
- **④ 平台协作 / 外部生态（`Platform Integration`）**：与 kinstall 平台定位并列或存在商业许可限制，明确边界。

## 2. 逐项深度调研剖析与工程避坑要点

### 2.1 数据库与 AI / 图引擎（MongoDB、Milvus、Neo4j）

#### 1. MongoDB（及替代路线 2026-10 实证真相）
- **版本与架构**：生产稳态选 **`8.0.37`**（2026-11-10）；`8.2.x` 处于功能预览线。标准生产拓扑为 **3 节点 Replica Set（PSS，禁用 Arbiter 防止 `w:majority` 写确认退化与回滚丢数）** 或 **Sharded Cluster（ConfigRS 3 节点 + ≥2 ShardRS + ≥2 `mongos`）**。
- **许可与替代品 2026-10 真实评估**：
  - **MongoDB CE 与 Percona Server for MongoDB (`PSMDB 8.0.32-14`) 均采用 SSPL**（非 OSI 开源）；PSMDB 的价值在于免费补齐了上游收费的 **静态加密（对接 OpenBao/KMIP）、审计日志、LDAP/OIDC 与热备**，配合 Apache-2.0 的 **Percona Backup for MongoDB (`v2.17.0`)** 实现 PITR 与 **Percona Operator (`v1.23.1`)**（注意：离线部署必须显式关闭默认遥测 `perconaTelemetry=false`，并关注 PSMDB 落后上游 CVE 补丁 2–4 周的窗口）。
  - **⚠️ 重大警示 — FerretDB `v2.7.0` 停滞风险**：2026-10 实证其自 2025-11 以来近 1 年未发版、2026-02 后 `main` 无提交、官网域名曾过期，且仍缺失多文档事务（`commitTransaction`/`abortTransaction`）与 RBAC，**严禁作为生产默认替代**。
  - **Linux Foundation DocumentDB（`v0.117-0` / `v1.0-RC2`，MIT）**：基于 PostgreSQL 17/18 + CNPG，Microsoft/AWS 主导进展活跃，但尚处 RC 阶段（不支持原地升级），待 1.0 GA 后评估纳入 PG 插件扩展。
- **kinstall 落地要点**：按 `ADR-052` 同等模式不进公共离线包；强制开启 SCRAM-SHA-256 + `keyFile`（0400）/ x.509 mTLS + 禁用 THP + XFS 数据盘 + 启动后强检未认证 `listDatabases` 必失败（防 `CVE-2026-82067` 类裸奔）。

#### 2. Milvus（AI 向量数据库 — 2026 重大架构拐点！）
- **核心架构演进**：自 `2.6.x`（最新 `2.6.26`，推荐生产稳态）和 `3.0.x`（最新 `3.0.5`，与 2.6 不兼容）起，Milvus 引入了基于对象存储的云原生 WAL 组件 **Woodpecker**，可内嵌于 Streaming Node 或独立运行，**彻底消灭了对重型 Apache Pulsar 的强制依赖**！同时解决了早期 Pulsar 2.8 不支持 `arm64` 的顽疾。
- **🚨 关键高危漏洞拦截**：旧版 `2.5.x` 存在 **`CVE-2026-26190`（CVSS 9.8）** —— 通过监控端口 `9091` 绕过鉴权直调 REST/系统接口！kinstall BOM **强制基线 ≥ `2.6.26` / `3.0.5`**，且默认防火墙仅向 Prometheus CIDR 开放 `9091`。
- **与 kinstall `Stack` 天作之合**：彻底替换 Milvus 官方默认捆绑的已归档 MinIO CE → 直接通过 `Stack` 对接 kinstall 的 **etcd + SeaweedFS S3（P6）**；硬件预检复用 D1 Facts 的 `x86_flags`（检查 `avx2`/`avx512`，arm64 检查 NEON/SVE）。

#### 3. Neo4j（图数据库 — 商业边界警示）
- **必须提前告知客户的硬边界**：Neo4j 2025–2026 系列 **Community Edition（GPLv3）严格仅支持单节点**，不支持集群高可用、不支持在线热备份、不支持 RBAC 与多库；上述高可用能力全部锁定在商业 Enterprise Edition。
- **kinstall 策略**：声明式包明确标注 `community` 仅限单机 + 定时冷备（`neo4j-admin database dump`）与停机恢复；客户持有商业 License 时放开 Enterprise 3 节点集群 + Helm 滚动升级；纯开源高可用图场景推荐 **PostgreSQL 18 + Apache AGE**（直接享有 P4 的 Patroni/CNPG 高可用与 PITR）。

### 2.2 底座级基础运行时与构建工具链（JDK 二进制、Maven、Npm/Node.js）

这三项**绝不能做成沉重的服务型插件**，而应抽象为底座/CI 构建节点通用的 **`runtime/*` 声明式工具链模块**，由上层所有 JVM/前端插件共享引用！

#### 4. JDK（二进制安装 — P0 基础底座能力）
- **2026-11 版本与安全基线**：
  - 主流默认 **Eclipse Temurin JDK 21 LTS**（`21.0.12+`）与 **JDK 25 LTS**（`25.0.4+`）；**强制要求包含 2026-11-18 CSPU 安全更新（修复 `CVE-2026-114938 "java4shell"`）及 2026-10 移除受污染 eMudhra CA 根证书的构建**；
  - 信创鲲鹏 arm64 可选 **华为毕昇 JDK 21**（针对鲲鹏指令集/KAE/GC 优化），阿里系/大堆电商负载可选 **Alibaba Dragonwell 21/25**。
- **多版本无冲突二进制安装规范（彻底告别污染宿主机默认 Java）**：
  - 安装目录：`/opt/kinstall/runtimes/jdk/<vendor>-<major>.<minor>.<patch>/`（如 `temurin-21.0.12+7`），并通过软链 `/opt/kinstall/runtimes/jdk/21` 指向当前 21 最新小版本；
  - 各中间件插件（Kafka / SkyWalking / RocketMQ / Seata / Jenkins / ZooKeeper）的 systemd unit 显式设置 `Environment=JAVA_HOME=/opt/kinstall/runtimes/jdk/21`，**不依赖、也不破坏客户主机原有的系统 JDK 8/11**；
  - 仅当用户在 Host Profile 显式指定 `setSystemDefault: true` 时，才写入 `/etc/profile.d/kinstall-jdk.sh` 并注册 `update-alternatives`；
  - **企业离线 CA 注入**：支持把平台自建 Root CA 自动通过 `keytool -importcert -cacerts` 幂等导入对应 JDK 的 `lib/security/cacerts`，避免 Java 服务连内部 HTTPS Harbor/OpenBao/ES 报 `PKIX path building failed`。

#### 5. Maven & 6. Npm / Node.js（客户端工具链 + 离线私服双层设计）
- **客户端二进制安装**：
  - **Maven**：默认 **`3.10.2`**（2026-11-22，兼容 JDK 8+）或 `3.9.16`；`4.0.0-rc-6`（需 JDK 17+，引入 build/consumer POM 拆分）列为可选预览。解压至 `/opt/kinstall/runtimes/maven/<ver>`，由 `template.render` 下发 `/etc/kinstall/maven/settings.xml` 强制 `<mirrorOf>*</mirrorOf>` 指向内网私服并禁用外部 Central 探测。
  - **Node.js / npm**：默认 **Node.js `26.13.1 Active LTS`** 或 **`24.22.3 Maintenance LTS`**（2026-11-11 安全版，含 `npm 11.19.1`，修复 2026-10 Node2Shell 漏洞）。官方 `.tar.xz`（`linux-x64`/`linux-arm64`）解压至 `/opt/kinstall/runtimes/node/<ver>`，下发全局 `/etc/npmrc` 指向内网私服 + `cafile` 信任内部 CA。
- **⚠️ 2026 离线私服选型红线**：
  - **警惕 Sonatype Nexus Repository Community Edition**：2025/2026 改版后已不再是纯粹开源（增加组件数/请求上限、强制外联回传遥测、HA/SSO 全收费），**不适合离线信创现场作为默认推荐！**
  - **kinstall 推荐开源私服组合（声明式包）**：
    - npm 专用轻量化：**Verdaccio**（MIT，~70 MB RAM，scoped uplink 代理 + 离线缓存 + htpasswd/LDAP）；
    - Maven 专用轻量化：**Reposilite**（Apache-2.0，轻量单 JAR）；
    - 多格式一站式（Maven + npm + PyPI + Go + OCI）：**Forgejo / Gitea Package Registry**（单 Go 二进制 ~116 MB RAM）或兼容 Nexus v1 REST API 的开源替代（如 Nexspence）。

### 2.3 分布式消息、协调与事务中间件（RocketMQ、Seata、ZooKeeper）

#### 7. Apache RocketMQ（`5.5.1` / `5.4.0` — 金融级业务消息队列）
- **与 Kafka 4.x 分工**：Kafka 4.x（P3）主攻海量日志削峰与流式数据总线；RocketMQ 5.x 主攻**事务消息、精确任意定时/延迟消息、严格顺序消息与金融电商业务解耦**（5.5.x 新增 Lite Mode 轻量订阅与 RocksDB 存储优化）。
- **生产 HA 架构（5.x Controller Mode）**：部署 **2+ NameServer** + **3 节点 Raft Controller**（可独立或内嵌于 NameServer）+ **多组 Master-Slave Broker（自动主从切换，无需旧版 3 副本 DLedger 写放大）** + **无状态 Proxy（gRPC 协议）**；强制关闭未认证外网 Remoting 端口并启用 ACL 2.0，预检 `vm.max_map_count >= 655360` 与 NVMe CommitLog 独立盘。

#### 8. Apache Seata（`2.6.0-incubating` — 分布式事务协调器）
- **双高可用模式**：
  - **模式 A（推荐免外部 DB 瓶颈）**：**3 节点 Seata-Raft 集群 + 2 节点 Seata NamingServer**（2.6.0 已原生支持 Raft 模式注册至 NamingServer 并支持 HTTP/2 Watch API，零第三方注册中心依赖、高 TPS）；
  - **模式 B（存量兼容）**：无状态 TC 节点 + 外置 PostgreSQL/MySQL（`global_table`/`branch_table`/`lock_table` 自动建表）+ Nacos/ZK/etcd。
- **全架构就绪**：官方直接提供 `linux/amd64` 与 `linux/arm64` 的 `2.6.0.jdk21` / `2.6.0.jdk25` 镜像及二进制包。

#### 9. Apache ZooKeeper（`3.9.7` / `3.8.8` — 存量协调器）
- **定位**：Kafka 4.x 已彻底移除 ZK；仅作为存量 Hadoop/HBase/Dubbo/旧版应用依赖提供 3/5 节点集群声明式包。
- **必配防坑参数**：强制 `autopurge.snapRetainCount=5` + `autopurge.purgeInterval=1`（防止事务日志打满根盘！）、`dataLogDir` 与 `dataDir` 分盘隔离、`4lw.commands.whitelist=stat,ruok,mntr,srvr`（禁止开放 `wchc`/`dump`/`*` 造成 DoS 与信息泄露）、启用 SASL/mTLS。

### 2.4 DevOps、协同与云原生平台组件（Harbor、GitLab、Jenkins、SonarQube、OnlyOffice、Rancher）

#### 10. Harbor（`v2.16.0` — 2026-11 里程碑版本！）
- **2026-11 重大利好**：`v2.16.0`（2026-11-09 发布）终于实现了 **官方完整 `amd64` + `arm64` 支持**、**用 Valkey 正式取代 Redis**、内置 DB 升至 **PostgreSQL 18**、并升级扫描器响应 2026-03 Trivy 供应链事件！
- **与内置 Zot 的分层定位**：
  - **Zot v2.1.23**（底座 D3 内置）：零依赖单二进制、极低内存，负责平台自身离线安装引导与边缘 Pull-Through 缓存；
  - **Harbor 2.16**（可选企业级 `Stack` 包）：面向客户多研发团队的**企业级镜像治理中心**（项目级自定义 RBAC、机器人账号、镜像复制、Proxy Cache、保留策略、cosign/Notation 验签）。
- **arm64 64K 页避坑（重要！）**：Harbor 2.16 容器内自带的 Valkey 在 arm64 64K 页宿主机上触发 `goharbor/harbor#24445` 崩溃；kinstall 在 64K 主机部署 Harbor 时**强制外部化三件套** —— `Stack` 直连 kinstall 64K 编译版 Valkey + PostgreSQL 18 + SeaweedFS S3，既根治 64K 崩溃又天然具备 Harbor 多副本 HA！

#### 11. GitLab（`19.5.6` — 企业代码与 CI/CD 平台）
- **架构与离线运维硬坑**：18.1+ 官方全面提供 `arm64` Docker 与 Omnibus 包（已覆盖 RHEL 8/9/10、Debian 12/13、Ubuntu 22.04/24.04/26.04）。
  - **资源红线**：单机 Omnibus 预检强制要求 **≥ 8 GB 内存（生产推荐 16 GB+）**，4 GB 机器必然 OOM；
  - **版本锁死**：`gitlab-backup restore` 严格要求目标实例与备份时**补丁号完全一致**，且跨版本升级必须严格按官方 `Upgrade Path` 停靠点逐级跳升（kinstall 升级计划器需内置停靠点表校验！）；
  - **轻量化备选**：对中小团队/边缘离线机房，同步提供 **Forgejo / Gitea** 声明式包（Go 单二进制，内存消耗仅为 GitLab 的 1/50，且内置 Maven/npm/OCI 私服）。

#### 12. Jenkins（`2.580.3 LTS` — 传统与混合 CI 调度）
- **2026 重大变更**：`2.555.1 LTS`（2026-05）已彻底移除 Java 17 支持，Controller 与全部 Agent **强制 JDK 21 或 JDK 25**（直接复用 `runtime/jdk` 21！）。
- **离线痛点根治**：传统手工安装 Jenkins 离线装 100 个插件必陷依赖地狱；kinstall 离线 Bundle 构建期调用官方 **`jenkins-plugin-cli`** 自动解析完整 `.jpi` 依赖闭包打包进离线制品库，安装期通过 **JCasC（`casc.yaml`）** 声明式注入 OIDC、Agent 凭据、Maven/JDK 工具路径，实现 100% 零人工向导无人值守交付。

#### 13. SonarQube（`Community Build 26.x` / 商业 `2026.5 LTA`）
- **版本体系变化**：原 Community Edition 已更名为 **SonarQube Community Build**（LGPLv3，月度发布 `26.x`，无 LTA，无多分支分析）；商业版为 **SonarQube Server**（LTA `2026.5`）。
- **硬前置依赖**：`2026.5` 起弃用 PG 14，**强制外接 PostgreSQL 15–18**（严禁生产用内置 H2！）；内置 Elasticsearch 进程要求主机应用 `search` Profile（`vm.max_map_count >= 524288`、`nofile >= 131072`）。

#### 14. OnlyOffice Docs（`10.0.0` — 在线文档协同引擎）
- **合规与并发红线**：社区版为 **AGPLv3** 且软限制 **20 路并发编辑连接**；超并发需客户导入商业 `license.lic`。
- **离线部署要点**：官方提供 `amd64`/`arm64` Docker 镜像（含麒麟 V10 专有说明）；容器内需挂载中文字体库目录（`/usr/share/fonts/truetype/custom` + 执行 `documentserver-generate-allfonts.sh` 否则中文文档转 PDF 乱码！）；强制启用 `JWT_ENABLED=true` 并由 kinstall 自动生成 256-bit 随机 `JWT_SECRET`；HA 模式通过 `Stack` 拆出外置 PostgreSQL + Valkey + RabbitMQ。

#### 15. Rancher（勘误 `ranker` — SUSE Rancher Manager `v2.14.2` / `v2.13.4`）
- **版本与架构**：Apache-2.0；**RKE1 已于 2025-07-31 正式 EOL**（2.12+ 彻底移除，仅支持 RKE2 / K3s / 导入外部标准 K8s）；支持全量 `arm64` 离线镜像清单。
- **与 kinstall 的清晰边界**：
  - Rancher 聚焦于 **Kubernetes 之上** 的多集群应用/Fleet 管控；kinstall 聚焦于 **裸金属/信创 OS 纳管初始化 + 二进制 K8s 交付 + 全套宿主机/容器/K8s 中间件安装运维**。
  - **推荐协作模式**：kinstall **不依赖** Rancher，而是提供可选的 **Rancher K8s Addon 声明式包**（在 kinstall 装好的高可用 K8s 上一键离线部署 Rancher HA），或允许客户将 kinstall 交付的 K8s 集群一键导入已有 Rancher 面板。
- *(歧义备忘：若您提问中的 `ranker` 实际指配合 Milvus 做 RAG 检索重排的 **AI Reranker 推理服务**（如 BGE-Reranker / TEI / vLLM），则归属远期 `E21` GPU/NPU 容器化声明式包范畴，后续可在 Milvus 专题中联合编排。)*
